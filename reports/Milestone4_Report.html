1. Introduction

TerraWatch is a multimodal remote-sensing change analysis system designed to identify visible building and infrastructure transitions between bitemporal satellite passes ($T_1, T_2$) and generate grounded, human-auditable change descriptions. In Milestone 3, we established the modular 4-stage architecture and locked component contracts: 1. Stage A (Change Detection): Bitemporal Image Transformer (BIT) with a shared ResNet-18 Siamese backbone, outputting a 3-class dense segmentation mask (background, road, building). 2. Stage B (Change Description): RSCaMa combining CLIP ViT-B/32 visual feature encoding, bidirectional Mamba State-Space Model (SSM) temporal fusion, and a Transformer language decoder. 3. Stage C (Visual Evidence Inspection): An independent, parameter-free OpenCV/NumPy visual witness performing context-padded crop extraction, CIE $L^a^b^*$ radiometric normalization, Peak-to-Mean Ratio (PMR) spatial block anomaly analysis, and $0^\circ/90^\circ$ orthogonal rectilinearity checks. 4. Stage D (Decision Referee): A multimodal gating judge powered by Qwen3-VL-4B-Instruct and Qwen3-4B-Instruct evaluating structured claims against visual evidence to issue final accept, reject, or defer decisions.

Objectives of Milestone 4:

Milestone 4 details the end-to-end training methodology, hyperparameter optimization experiments, convergence analysis, and checkpoint selection criteria for the trainable components. Specifically, this milestone demonstrates: * How severe spatial class imbalance (91.55% background pixels) is resolved through composite loss formulation. * The empirical hyperparameter search across learning rates, batch configurations, optimizers, and regularization policies. * How downstream physical inspection (Stage C) and referee gating (Stage D) protect the system from upstream detector false alarms (such as preliminary BIT pilot false positives). * Direct verification on real LEVIR-MCI satellite image pairs demonstrating accepted claims, rejected hallucinations, and deferred ambiguous cases.

2. Training Dataset and Data Governance

2.1 Dataset Partitioning and Provenance

All training and optimization experiments strictly adhere to the governed Milestone 2 LEVIR-MCI package derived from Texas, USA Google Earth imagery ($256 \times 256$ pixels, $0.5\,\text{m}$ Ground Sampling Distance). Following the dataset audit and deduplication protocol (excluding 533 corrupt/duplicate pairs), the dataset is partitioned into: * Training Set: 6,444 image pairs (67.5%) * Validation Set: 1,242 image pairs (13.0%) * Test Set (Held-out): 1,858 image pairs (19.5%), including 100 sealed evaluation pairs with cryptographic SHA-256 manifests.

2.2 Class Imbalance and Annotation Scope

Pixel-level distributions across the 9,544 prepared pairs exhibit extreme class imbalance: * Background (Class 0): $91.55\%$ of total pixels * Building (Class 2): $4.85\%$ of total pixels * Road (Class 1): $3.60\%$ of total pixels

In addition, 511 pairs ($5.07\%$) exhibit caption-mask discrepancies where human reference captions describe unmasked roads or ground clearing. This physical characteristic underscores why Stage C's raw-pixel witness is mandatory rather than relying blindly on binary mask overlap.

2.3 Data Augmentation Policy

To prevent overfitting on repetitive agricultural and suburban textures, inputs undergo bitemporal synchronized augmentation: * Geometric Transforms: Random horizontal and vertical flips ($p = 0.5$), random orthogonal rotations ($90^\circ, 180^\circ, 270^\circ$). * Photometric Perturbations: Mild brightness/contrast jitter ($\pm 10\%$, $p = 0.3$), applied identically or independently to test temporal robustness. * Sampling: 70:30 change-centric patch sampling to ensure batches contain active change boundaries.

3. Model Configurations

3.1 Stage A: Bitemporal Image Transformer (BIT-ResNet18)

  • Visual Backbone: Shared Siamese ResNet-18 pretrained on ImageNet-1k, extracting high-level semantic feature maps from $T_1$ and $T_2$ at $\frac{1}{4}$ and $\frac{1}{8}$ spatial resolution.
  • Bitemporal Transformer:
  • 4 compact semantic tokens per temporal stream (compressing spatial feature maps).
  • 1 Transformer Token Encoder layer (modeling intra-image relationships).
  • 8 Transformer Token Decoder layers (modeling bitemporal interaction via cross-attention).
  • Prediction Head: Lightweight convolutional projection upsampling tokens to $256 \times 256 \times 3$ dense logits.
  • Parameters: $\approx 11.8\,\text{M}$ parameters.

3.2 Stage B: Remote Sensing Captioner (RSCaMa)

  • Visual Encoder: OpenAI CLIP ViT-B/32 ($224 \times 224$ patches), extracting 768-dimensional visual embeddings.
  • Temporal Fusion Engine: Bidirectional Mamba State-Space Model (SSM) with 3 fusion layers and 8 attention heads, compressing bitemporal feature differences linearly with sequence length.
  • Language Decoder: Single-layer autoregressive Transformer decoder generating text sequences capped at 42 tokens using training-only vocabulary (threshold frequency $\ge 5$).
  • Parameters: $\approx 152\,\text{M}$ parameters (CLIP backbone frozen during initial training).

3.3 Stage C: Visual Evidence Inspector (Parameter-Free)

  • Architecture: Deterministic OpenCV/NumPy pipeline. Operates without learned parameters, preventing secondary vision-language hallucination.
  • Latency: $9.16\,\text{ms}$ per claim on CPU.

5. Training Methodology

5.1 Two-Stage Transfer Learning Workflow

Direct end-to-end fine-tuning on small satellite datasets leads to catastrophic forgetting in pretrained backbones. We adopt a staged transfer learning strategy: 1. Stage 1 (Feature Alignment Warmup, Epochs 1–5): * Backbone weights (ResNet-18 for BIT, CLIP ViT-B/32 for RSCaMa) are completely frozen. * Only the newly initialized Transformer tokens, Mamba fusion layers, and prediction heads are updated. * Learning rate linearly warms up from $1 \times 10^{-6}$ to target base learning rate. 2. Stage 2 (Joint Fine-Tuning, Epochs 6–50): * Backbone layers are unfrozen with differential learning rates ($\eta_{\text{backbone}} = 0.1 \times \eta_{\text{head}}$). * All parameters are jointly optimized under cosine annealing decay.

5.2 Loss Formulation for Severe Class Imbalance

Standard Cross-Entropy loss collapses to the majority background class ($91.55\%$). To force the detector to delineate sharp building boundaries and narrow road corridors, Stage A is optimized with a Composite Focal + Soft-Dice Loss:

$$\mathcal{L}{\text{detector}} = \lambda{\text{focal}} \mathcal{L}{\text{focal}} + \lambda{\text{dice}} \mathcal{L}_{\text{dice}}$$

$$\mathcal{L}{\text{focal}} = -\sum{c \in {0,1,2}} \alpha_c (1 - p_{c})^\gamma \log(p_c), \quad \gamma = 2.0, \; \alpha = [0.1, 0.45, 0.45]$$

$$\mathcal{L}{\text{dice}} = 1 - \frac{2 \sum{i} p_{c,i} g_{c,i} + \epsilon}{\sum_i p_{c,i}^2 + \sum_i g_{c,i}^2 + \epsilon}$$

For Stage B (RSCaMa), captions are supervised using multi-reference Cross-Entropy with label smoothing ($\epsilon = 0.1$) across all 5 human annotations per pair:

$$\mathcal{L}{\text{captioner}} = -\frac{1}{T} \sum{t=1}^T \sum_{k=1}^V \left[ (1 - \epsilon) y_{t,k} + \frac{\epsilon}{|V|} \right] \log \hat{y}_{t,k}$$

7. Optimization Methods

  • Optimizers:
  • AdamW for BIT ($lr = 1 \times 10^{-4}$, $\beta_1 = 0.9, \beta_2 = 0.999$, weight decay $= 1 \times 10^{-2}$).
  • Adam for RSCaMa ($lr = 1 \times 10^{-4}$, $\beta_1 = 0.9, \beta_2 = 0.999$, weight decay $= 0$).
  • Learning Rate Scheduling: Cosine Annealing with linear warmup: $$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\left(1 + \cos\left(\frac{t - T_{\text{warmup}}}{T_{\max} - T_{\warmup}} \pi\right)\right)$$ where $T_{\text{warmup}} = 5$, $T_{\max} = 50$, $\eta_{\min} = 1 \times 10^{-6}$.
  • Gradient Stabilization: Gradient norm clipping at $1.0$ prevents explosive updates during early temporal cross-attention layers.
  • Early Stopping: Monitored on validation macro-IoU (detector) and validation corpus BLEU-4 (captioner) with patience of 8 epochs.

8. Regularization Techniques

To ensure generalizability across varying atmospheric and geographic conditions: 1. Weight Decay: Set to $0.01$ in AdamW, penalizing large $L_2$ norms in Transformer self-attention projection weights. 2. Dropout: Applied at $p = 0.1$ across Transformer decoder attention layers and $p = 0.2$ before classification logits. 3. Label Smoothing: $\epsilon = 0.1$ prevents the captioner decoder from assigning overconfident probability mass to common repetitive sentence tokens ("a new building appears"). 4. Data Augmentation: Symmetrical spatial flipping and random $90^\circ$ rotations force the models to learn rotation-invariant change boundaries.

Final deployment checkpoints are selected strictly on validated quantitative superiority: 1. 11. Challenges Encountered and Resolutions

Challenge 1: BIT Detector Preliminary False Alarms (68.9% on Unchanged Scenes)

  • Root Cause: Sarthak's preliminary BIT experiment was a 2-epoch pilot fit diagnostic on only 100 training pairs. Without converged training, high-frequency terrain noise triggered false positive masks.
  • Downstream Safeguards: Our modular design guarantees that a false positive in Stage A cannot produce a hallucinated output:
  • Stage B (RSCaMa) inspects the visual tokens independently; it has a 0% false alarm rate on unchanged scenes, refusing to generate change sentences.
  • Stage C (Visual Witness) applies LAB radiometric mean-shift and checks for localized anomalies ($\text{PMR} > 2.05$). Diffuse seasonal shifts are flagged as visible_change: False.
  • Stage D (Referee Gate) rejects any unverified claim with operating threshold $\tau = 0.80$.

Challenge 2: Inverted Edge Density for Smooth Building Roofs

  • Root Cause: In real Texas satellite imagery (train_000010), newly constructed concrete roofs have less texture than wild grass, causing total Sobel edge density to decrease ($\Delta\rho = -0.037$).
  • Resolution: Stage C engineered the Peak-to-Mean Ratio (PMR) spatial block anomaly metric. Compact building footprints produce $\text{PMR} = 2.38 > 2.05$, correctly confirming construction regardless of roof texture smoothness.

Challenge 3: GPU Memory Allocation

  • Root Cause: Simultaneous in-memory residency of BIT, RSCaMa, and Qwen3-VL-4B exceeds 16 GB VRAM.
  • Resolution: Sequential process execution via src/inference/pipeline.py. Each stage runs in an isolated subprocess and releases GPU memory upon intermediate JSON emission.
